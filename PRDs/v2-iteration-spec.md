# 快找房 v2 迭代规格说明（基于你的确认）

本文档在 v1/v2 PRD 基础上，结合你的确认与补充需求整理，作为在 **v1 仓库内直接修改** 的实现依据。

---

## 一、首页与统计

- **统计口径**：按日统计。
- **数据来源**：新表（见下方数据模型）。
- **指标**：每日房源数量、每日新增用户数，取 **前一日** 数据；上架/审核/签订数量、收益金额等按文档约定（昨日或按时间查询）。
- **图表**：用户活跃度折线图、房屋数量柱状图，按日维度，数据来自新表。

---

## 二、登录与账号

- **记住密码**：支持“记住密码”并回填（勾选记住后下次打开登录页自动填充账号+密码）。
- **登录身份**：不仅 admin 超管，**用户模块中维护的账户+密码** 也可作为登录凭据；系统用户来自用户表，用 **账户名 + 密码** 登录。
- **个人设置**：可修改当前登录用户密码；账户名称、姓名、联系方式、角色展示与编辑同 v2 文档。

---

## 三、天气

- 使用 **指定第三方 API** 查询真实天气。
- 展示多项信息（温度、位置、风向、未来五天等），UI 高端、信息完整。
- 推荐后端代理第三方 API 以便隐藏 Key 并统一鉴权。

---

## 四、签约模块（全新）

- **样式**：与房源、用户、角色模块一致（左侧菜单 + 列表 + 顶部“左侧搜索、右侧新增”）。
- **列表列**：签约小区名称、房东姓名及联系方式、租客姓名及联系方式、位置、签约价格、房源具体信息(楼栋+单元+楼层)、房屋照片、签约时间。
- **数据关联**：签约关联某条房源（选房源后带出该房源的楼栋/单元/楼层/照片等展示）。
- **功能**：增删改查；删除、添加、编辑按钮与其他模块一致。

---

## 五、房屋模块补充

- 增加 **楼栋、单元、楼层** 字段；列表增加“房源具体信息”列，显示格式：楼栋+单元+楼层。
- 其余按 v2：图片、位置、出租用户名称、审核流等。

---

## 六、用户模块补充

- 用户表增加 **密码** 字段（存储加密/哈希）。
- **列表**：密码列脱敏显示（如 ****** 或“已设置”）；**小眼睛仅放在编辑弹窗**内，用于切换明文/密文。
- **新增用户弹窗**：增加密码项，支持小眼睛切换明文/密文。
- **个人用户设置**：支持修改当前登录用户密码。
- **登录**：用户表账户+密码可作为登录凭据。

---

## 七、角色与权限

- **角色**：预置三个——最高管理员、管理员、普通业务员；后期可在角色模块添加。
- **最高管理员**：拥有所有模块权限（首页、房源、用户、角色、签约）。
- 签约模块权限：在 RBAC 中明确（如业务员可看+增，管理员可删改）。

---

## 八、代码与数据

- **代码**：在 **v1 仓库内** 直接修改。
- **数据库**：SQLite → MySQL；新增/扩展表：Users(密码)、Houses(楼栋/单元/楼层)、Roles、签约表、统计用表或按日统计逻辑。

---

## 九、实现顺序建议

1. 后端：MySQL + 新表与迁移 + 种子数据（admin + 三角色）。
2. 后端：JWT + RBAC + 全局异常/日志/参数校验。
3. 后端：签约 API、统计 API、天气代理 API。
4. 前端：登录（JWT、记住密码、用户表账号密码登录）+ 个人设置改密码。
5. 前端：首页大盘（天气、指标、ECharts）+ 签约模块页。
6. 前端：房源/用户/角色/签约 表单与列（密码小眼睛、楼栋单元楼层、签约列等）。

---

- **签约与房源**：签约**关联某条房源**（选房源后带出楼栋/单元/楼层/照片等）。
