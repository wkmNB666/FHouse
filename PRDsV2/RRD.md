产品需求文档 (PRD)：快找房 v2.0 (生产级商业化版)
1. 项目概述
产品名称：快找房 v2.0


产品目标：通过房屋信息展示让租房者挑到合适房源 。在 v1.0 基础上进行系统级重构，引入企业级安全认证、角色权限隔离与可视化数据大盘，打造具备线上商用能力的成熟稳定的管理系统。

技术栈规范：

前端：React 18 + TypeScript + Vite + Ant Design (UI) + ECharts (可视化)。

后端：C# .NET 8 Web API。


数据库：MySQL (取代 v1.0 的 SQLite) 。默认超级管理员账号：admin，密码：wkm112233 。

2. 系统架构与工程规范 (基础设施)
为确保系统在生产环境的稳定与安全，必须落实以下规范：


部署与网络：前端 axios 的 baseURL 配置为相对路径（如 /api），生产环境交由 Nginx 统一进行反向代理转发 。后端的 .NET 8 Web API 部署后，必须使用 Systemd 或 Supervisor 进行进程守护，确保服务崩溃后自动重启 。


安全鉴权 (Auth)：废弃模拟登录，引入标准的 JWT (JSON Web Token) 鉴权 。前端通过 axios 拦截器在请求头自动携带 Authorization: Bearer <token> 。

健壮性保障：

引入全局异常处理中间件 (Global Exception Handler)，统一返回标准化 JSON 错误格式（如 { "code": 500, "message": "服务器开小差了" }），严禁暴露底层堆栈 。

引入 Serilog 或 NLog 进行结构化日志收集，按天记录至服务器本地 。

控制器层利用 DataAnnotations 或 FluentValidation 进行严格参数校验 。

前端性能与体验：

采用真·服务端分页，前端传入 pageIndex 和 pageSize，EF Core 配合 Skip() 和 Take() 实现 。

axios 拦截器加入全局 Loading (Spinners) 与请求防抖 (Debounce) 。

3. 核心业务模块详解
3.1 登录与全局 Header 模块

登录策略：初次登录不显示账户信息；若浏览器之前成功登录过，则保留并显示历史账号密码信息 。加强登录安全校验规则，向优秀开源项目对齐 。

全局 Header 优化：

登录后默认重定向展示首页模块 。

移除原 Header 中的天气信息 。

右上角个人用户设置变更为点击唤出弹窗，包含：账户名称、姓名、联系方式、角色，提供确定修改与取消关闭按钮 。

3.2 首页数据大盘 (Home Dashboard)

功能描述：弃用原首页展示房源模块的逻辑，全面升级为可视化数据看板 。


天气看板：扩充天气展示区域，包含：天气温度、位置、风向、未来五天天气情况 。


核心数据指标：新增一栏卡片展示：上架房源数量、审核房源数量、房源签订数量、收益金额。默认统计昨日数据，右侧配备“按时间查询统计”按钮 。

可视化图表 (ECharts)：


用户活跃度折线图 。


房屋数量柱状图 。

3.3 房源模块 (Housing Module)

数据展示：列表新增展示列：图片、房屋位置、出租用户名称 。


图片上传支持：统一表单新增一行图片上传入口，支持多图上传 (png/jpg 格式) 。图片传至后端静态目录由 Nginx 访问 ；上传成功后，在列表页支持裂变缩略图展示 。

审核业务流：

行操作列在编辑、删除旁新增**“审核”**按钮 。

状态视觉：审核通过后该按钮消失，未审核/未通过时按钮高亮显示 。

点击交互：唤出房源审核弹窗，包含“备注”输入框及“通过”、“未通过”操作按钮 。

3.4 用户模块 (User Module)

数据展示：列表新增展示列：角色 。

行级操作：在编辑、删除旁，新增**“修改角色”**按钮。点击唤出角色分配下拉框（数据源自角色列表）。

新建用户逻辑：统一表单中增加一行“角色分配”下拉框（展示如最高管理员、管理员、业务员）。若未主动勾选，系统底层默认赋予新用户**“普通业务员”**角色。

3.5 角色与权限模块 (Role & Permission Module)

功能描述：实现基于角色的访问控制 (RBAC) 。


数据展示：左侧新增独立菜单 。列表展示：角色名称、角色描述、创建时间 。


权限配置交互：列表右侧提供**“权限配置”**按钮 。点击唤出权限面板，左侧为可勾选的菜单模块权限（房源、用户、角色），打勾后该角色才可见对应模块；右侧为下拉多选的“角色成员”关联操作 。

3.6 统一动态表单 (Dynamic Form V2.0)
采用一套通用组件处理 添加房屋 / 添加用户 / 添加角色 。根据传入的 type 动态渲染对应的 Label 和输入控件（含房源的图片上传和用户的角色下拉选择）。

4. 核心权限流转规则 (RBAC Rules)
为保证系统逻辑严密，必须在代码层面落实以下硬性权限隔离：

普通业务员：仅拥有登录、查看首页、添加与查看房源、查看自身信息的权限。无权执行任何删除操作，无权访问角色模块。

管理员 / 最高管理员：拥有全局删除权限。核心特权：房源模块中的**“审核”**资格（查看审核按钮、执行审核操作）严格限制为只有这两类角色可使用。
